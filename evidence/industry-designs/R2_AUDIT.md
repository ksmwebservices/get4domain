# Industry designs round 2: Phase S0 audit (16 Oct 2026)

## What we found, in plain sentences

1. **Round 1 stays whole.** The category packs (24, with flow family, four designs and starter content), the sample markers, `siteStatus`, SEO per host (canonical, `robots.txt`, `sitemap.xml`, noindex rules), the Page content, Items, Template and Sample content tabs, the Category packs admin screen, and the 13 round 1 test ids are all kept and keep passing. The 96 built-in designs stay as the fallback and are not extended.
2. **What the theme packages replace.** Only the kit section renderer, and only for a vendor whose design is an imported theme. Everything the vendor writes (site document, items, pictures, hours, social links, sample markers) is read the same way by both renderers, so switching never loses content.
3. **Where a design is rendered today.** `app/site/[subdomain]/[[...rest]]/page.tsx` calls `buildSiteDocModel` (`engine/sitedoc/build.ts`), which picks the design from `cms.designKey` and the category pack and builds a `KitSiteModel`; `KitRenderer` draws it. The smallest change that lets a design be built-in or imported is the value of `designKey`: a key of the form `t:<themeId>` means an imported theme package, anything else is a built-in design. The public site payload gains a `themePackage` block only when that key resolves to a theme the vendor may use.
4. **There is already a different theme path, and it stays untouched.** The older `WebsiteTheme` rows hold raw HTML pages and JavaScript rendered in an isolated iframe (`engine/raw-theme-frame.tsx`; the MR Travels theme uses it) and a one-time paid unlock (`VendorTemplateUnlock`, platform Razorpay, price plus 18 percent GST, invoice through `InvoicesService.createPaidInvoice`). It carries scripts, so it cannot be the marketplace for a multi-tenant system. The new `ThemePackage` path is separate, server-rendered, script-free and yearly. The old rows and the old unlock keep working for the vendors that use them. The new purchase mirrors the old payment mechanism (order, capture check against Razorpay, invoice) instead of inventing a payment system.
5. **Mobile navigation today** is `EngineBottomNav.tsx` (a tab bar of at most five labels built per page by the builder, an optional raised last item) or two call-to-action bars. It has no "More" sheet, its slots are not pack data, and the primary action is a scroll to a form.
6. **Booking and enquiry today** live in one `KitEnquiry` section at the bottom of the page. Every call to action is an anchor to `#enquiry`. A long page means a long scroll before a visitor can act. The flows underneath are right and are reused: `engine.enquiry` (lead into the vendor CRM) and `engine.checkout.request` and `engine.checkout.order` (orders), through the Action Registry and `POST /engine/public/:subdomain/actions/:intent`.
7. **Footer today** is `KitFooter` or `DesignFooter` (columns, centred, minimal): brand, contact, four social links as text, no hours block, no icons, no legal links. The header has no WhatsApp chip and its button scrolls to the form.
8. **Pages today** are the home page plus vendor-written pages at `/p/<slug>`; items have no URL of their own. Themes must be multi-page with item detail pages, so the router and the sitemap need the page list and item slugs.
9. **Packs and settings.** Pack config has no bottom-nav slots, popup steps or labels (doctor, stylist, trainer, faculty, agent). These become pack data (`config.shell`) so a new category needs no code.

## Decisions for round 2 (also in `docs/v2/INDUSTRY_DESIGNS_R2_PROGRESS.md`)

- Theme packages are rendered by converting the sanitised HTML into React elements on the server (no `dangerouslySetInnerHTML`), so engine tags become the real components and nothing else can run.
- The sanitiser and the lint are one module in the API (`backend-api/src/themes/core`); the lint command line loads the same TypeScript through the TypeScript compiler, so KSM needs no build and the two can never disagree.
- Assets live in a table in the database (backed up with everything else, no new volume), served by the API with immutable cache headers.
