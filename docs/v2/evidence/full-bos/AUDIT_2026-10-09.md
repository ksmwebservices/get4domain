# Full BOS audit — did it work or not (2026-10-09)

Method: the real compiled API over an isolated in-memory Postgres (`backend-api/scripts/bos/audit.js`, re-runnable), one seeded COMMERCE vendor shaped like Step N Rock (footwear: products with sizes/colours, tracked stock, website, a website order). Nothing was fixed while auditing. UI-only facts come from the production-build walkthrough in `docs/v2/evidence/dashboard-v2/WALKTHROUGH.md` and from reading the code, and are marked as such.

**Counts over 55 registry features:** WORKS 22 · PARTIAL 6 · BROKEN 2 · NOT BUILT 25.

## Plain answer: did products work?

**Selling works, billing and books do not.** A product created in My Products shows on the website, can be put in a cart, becomes an order, reserves stock exactly once, and the owner can mark it paid. Stock history is a real ledger. After that the chain stops: the order creates a CRM lead but **no customer record**, nothing turns an order into a customer invoice, there are no receipts, part payments, outstanding amounts or credit notes, website sales carry no GST, and the Accounts screen cannot see a paid website order (it reads manual invoices only). There are **three separate product stores**; only one of them feeds the website, orders and stock.

## Known bugs reproduced

- **B1 Website Manager save:** REPRODUCED — saving back what the screen loaded returns HTTP 400: `{"success":false,"statusCode":400,"message":["property id should not exist","property vendorId should not exist","property businessHours should not exist","property createdAt should not exist","property updatedAt should not exist"],"data":null,"timestamp":"202…`. Cause: the form sends read-only fields (id, vendorId, createdAt, updatedAt, businessHours) and the API refuses unknown properties.
- **B2 Razorpay Key ID shows an e-mail:** cause found in code: the Key ID is a plain text input directly before a password input with no `autocomplete` attributes, so the browser fills the saved login e-mail into it (`app/dashboard/payments/page.tsx`). The server stores whatever text it is given with no format check. Whether any live vendor row already holds a non-`rzp_` value cannot be read from here (the audit never touches production): `backend-api/scripts/bos/razorpay-key-report.js` is a read-only report for KSM to run on the VM.
- **B3 AI credit ₹250 vs ₹499:** `go-live/page.tsx` hard-codes "₹499 / ₹1,299 AI Studio credit included" (the annual list amount) while the vendor term shows the prorated credit for its length (₹250 for a half-year Essentials term). Several marketing pages repeat the annual figures. One source of truth is needed.
