# V3 Public Site: Backend and Platform Gaps

Everything the public site needs that the backend or the live app does not give yet, with the shape the front end assumed. Where a route is missing the screen says "not available yet" (or uses the mock layer in review); nothing is faked in real mode.

Owner column: **B** = backend work, **L** = live app (existing files), **O** = owner decision.

| # | Owner | Gap | What the front end does meanwhile | Assumed shape or fix |
|---|---|---|---|---|
| G1 | B | No public route starts a claim from a listing. Claim links are staff-issued; the OTP routes need the link token. | `POST /directory-api/claim/start` forwards to the assumed route. A 404 or 405 shows "Starting a claim from this page is not available yet". Owners with a claim link use `/claim/{token}` today. | `POST /v3/claim/start` body `{ businessSlug }` answers `{ token }` (or the wrapped form). Public, rate limited, uniform for unknown or already claimed (`DIRECTORY_STATE_INVALID`). The token then drives the existing `status`, `otp/request`, `otp/verify` routes. |
| G2 | B + vendor app | No token handoff to the vendor Vite app. | Sign-in and sign-up here check the credentials, drop the tokens and send the visitor on to `NEXT_PUBLIC_VENDOR_APP_URL`, where they sign in once more. | Either the vendor app accepts a one-time code in the URL fragment, or the public screens only link to the vendor app's own login. Owner decision. |
| G3 | B | The format of `businessId` in `/v3/go/{id}` is not documented. `/go/[slug]` is the live campaign page. | The middleware treats a `/go/{segment}` as a click-out only when it is a uuid or a cuid (fixture ids in mock mode); everything else still reaches the campaign page. | Document the id format, or move the click-out to an unambiguous prefix such as `/out/{id}` (then the middleware branch goes away). |
| G4 | B | No public listing-state field (`UNCLAIMED_LISTING`, `DRAFT_SITE`, `CLAIMED`, `LIVE`). The page model has `claimed` and `verified` only. | State is derived: not claimed, claimed with no site, claimed with a site. `DRAFT_SITE` is never derived (it is not public). | Add `listingState` to `PublicBusinessView` and to `BusinessFacts`. |
| G5 | B | The business page model has no business id and no services list. | The backlink block id is taken from the model's click-out address. A business with no click-out gets no backlink block. The services section is not rendered. | Add `businessId` and `services: { name, description }[]` to `BusinessFacts`. |
| G6 | B | The firm identity (name, address, GSTIN) has no admin setting. | One typed settings object in the repo (`lib/v3-public/firm.ts`), GSTIN shown only when set. | `GET /v3/public/firm` answering `{ name, address, gstin: string \| null }`, editable by SUPER_ADMIN; the front end then reads it with a short revalidate. |
| G7 | B | `RESERVED_SEGMENTS` in the backend URL scheme lacks `legal`, `claim`, `account`, `directory`, `sitemaps`. A city with one of these slugs could not be reached. | The fixed routes win over the directory by routing order. | Add them to `RESERVED_SEGMENTS`. |
| G8 | L | A removed business (410) cannot be sent as a real 410 from an app-router page; it renders a "no longer listed" page with 200. | The page is `noindex, nofollow`. | Handle in a route handler or at the proxy if a real 410 is wanted. |
| G9 | L | The live root `src/app/loading.tsx` flushes a loading shell before any page runs, so `notFound()` on any dynamic page is sent as HTTP 200 with a noindex page. Verified here: with the file removed, the same code answers a real 404. For the directory this means an unknown directory address is a soft 404 (200, noindex) while the flag is on. Flag off is unaffected (the live site's unknown addresses stay real 404s; verified). | Unknown addresses render the standard not-found page with noindex. | Owner decision before go-live: remove or narrow `src/app/loading.tsx` (a live-site change: it would also fix soft 404s on `/demo/*` and other dynamic pages). |
| G10 | L | The root layout injects site-wide JSON-LD (SoftwareApplication offers named "Workspace" and "BOS", Organization, WebSite) into every page, including the directory pages. | Nothing: editing it is outside this slice. | Before go-live, move that JSON-LD into `(marketing)/layout.tsx` or guard it by path. |
| G11 | O | The model's home path is `/`, which the live marketing home owns. The directory home is served at `/directory` and renders that model; its canonical and breadcrumb come from the model, so the canonical points at `/`. | Home is noindex while the directory pages are not indexable. | Decide the final home. Either the backend home model gets a `/directory` path, or the marketing home links to the directory and the model's canonical is overridden server side. |
| G12 | B | No registered error code for "email is switched off". | Any HTTP 503, or a code containing MAIL or EMAIL with OFF, DISABLED or UNAVAILABLE, shows the kind "email is switched off" screen. | Register `MAIL_DISABLED` (HTTP 503) on the OTP request route. |
| G13 | B + vendor app | Approval (`POST /v3/me/claim/approve`) needs the owner's bearer token, so it is done in the vendor app. The public site cannot know when the site went live. | `/claim/live` is the go-live notice page; the vendor app can send the owner back to it. | Vendor app redirects to `/claim/live` after a successful approve. |
| G14 | B | Password reset emails link to the backend's `frontendUrl` (`/reset-password?token=`), not to this site. | `/account/forgot-password` requests the link only. | Confirm `frontendUrl` is the vendor app or the main site, and that the reset screen exists there. |
| G15 | B | Rate limits are per IP. The public site calls the API from the server, so the API sees the server unless it trusts `X-Forwarded-For`. | The visitor address is forwarded in `X-Forwarded-For`. | Make sure the API's trusted proxy setting accepts it from the app server; otherwise all visitors share one limit. |
| G16 | B | `GET /v3/directory/businesses` sends `phone` for claimed businesses. | The front end types drop it and never render it. | Optional: stop sending it on this public route. |
| G17 | O | Amendments 11 to 14 are not in `get4domain-site`; the build followed the backend docs for Part B. | n/a | Add the files so the build can be checked against them. |
| G18 | O | Legal texts are drafts (see `PUBLIC_SITE.md`). | Every legal page shows a draft banner. | Counsel review before the flag goes on in production. |
