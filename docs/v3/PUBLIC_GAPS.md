# V3 Public Site: Backend and Platform Gaps

Everything the public site needs that the backend or the live app does not give yet, with the shape the front end assumed. Where a route is missing the screen says "not available yet" (or uses the mock layer in review); nothing is faked in real mode.

Owner column: **B** = backend work, **L** = live app (existing files), **O** = owner decision.

| # | Owner | Gap | What the front end does meanwhile | Assumed shape or fix |
|---|---|---|---|---|
| G1 | B | No public route starts a claim from a listing. Claim links are staff-issued; the OTP routes need the link token. | `POST /directory-api/claim/start` forwards to the assumed route. A 404 or 405 shows "Starting a claim from this page is not available yet". Owners with a claim link use `/claim/{token}` today. | `POST /v3/claim/start` body `{ businessSlug }` answers `{ token }` (or the wrapped form). Public, rate limited, uniform for unknown or already claimed (`DIRECTORY_STATE_INVALID`). The token then drives the existing `status`, `otp/request`, `otp/verify` routes. |
| G2 | B + vendor app | No token handoff to the vendor Vite app. | Sign-in and sign-up here check the credentials, drop the tokens and send the visitor on to `NEXT_PUBLIC_VENDOR_APP_URL`, where they sign in once more. | Either the vendor app accepts a one-time code in the URL fragment, or the public screens only link to the vendor app's own login. Owner decision. |
| G3 | B | The format of `businessId` in `/v3/go/{id}` is not documented. `/go/[slug]` is the live campaign page. | The middleware treats a `/go/{segment}` as a click-out only when it is a uuid or a cuid (fixture ids in mock mode); everything else still reaches the campaign page. | Document the id format, or move the click-out to an unambiguous prefix such as `/out/{id}` (then the middleware branch goes away). |
| G4 | B | No public listing-state field (`UNCLAIMED_LISTING`, `DRAFT_SITE`, `CLAIMED`, `LIVE`).
